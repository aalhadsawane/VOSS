\section{Related Work}
\label{sec:related}

\textbf{Cold starts and serverless scheduling.} Platforms decide when to keep sandboxes alive or start them early, for example
by learning each application's idle times~\cite{shahrad2020wild} or treating keep-alive as caching~\cite{fuerst2021faascache},
and make start-up faster with lighter sandboxes and snapshots~\cite{agache2020firecracker,oakes2018sock,ao2022faasnap,cadden2020seuss}.
Placement schedulers sample a few machines~\cite{ousterhout2013sparrow}, move the scheduler into a switch~\cite{kettaneh2020falcon},
or pack long jobs onto fleets~\cite{verma2015borg}; ALPS schedules function processes inside one machine~\cite{fu2024alps}. All
assume trusted machines that stay up, so a warm sandbox disappears only by policy and nothing resembles a key whose release
costs time and adds exposure. We use the Azure histogram policy as our strongest keep-alive baseline.

\textbf{Service placement and request routing.} Edge computing often places services on a slow timescale
and routes requests on a fast one~\cite{farhadi2021ton,tang2024rmws}. \voss{} shares this structure, with provisioning in the role of
service placement and request placement in the role of routing; what differs is that the placed resource is trust,
whose cost is exposure, on machines that disappear with estimated probabilities, protected against worst-case losses. Our
provisioning algorithms draw on submodular maximisation~\cite{nemhauser1978,harshaw2019}, the
convexity of the Erlang loss formula~\cite{messerli1972}, and budgeted robustness~\cite{bertsimas2004price}.

\textbf{Volunteer and confidential computing.} BOINC runs each task several times and compares results~\cite{anderson2002seti,anderson2004boinc},
which multiplies cost and exposes inputs; \voss{} uses attestation instead. Confidential serverless designs protect code from
the operator on provider servers~\cite{arnautov2016scone,wallet2025,segarra2024sesame,misono2025cvm} but do not handle machines
that vanish, nor schedule trust as a resource. Platforms on harvested or edge capacity~\cite{zhang2021harvest,rausch2021edge}
handle announced evictions by trusted owners.

\textbf{Failure detection and coordination.} Trusted components reduce the replication needed for Byzantine
agreement~\cite{levin2009trinc,veronese2013minbft}; we use attestation to remove the need for agreement, since an attested
machine can stop but not lie. Heartbeat detectors, including $\varphi$-accrual~\cite{hayashibara2004phi}, cannot see gray
failures~\cite{huang2017gray}; we check returned work. Duplicating slow requests cuts tail latency~\cite{dean2013tail}; we
duplicate only at-risk idempotent requests, within a budget.
