\title{VOSS: Scheduling Attested Session State for Serverless Computing on Volunteer Machines}

\author{Aalhad Sawane}
\affiliation{\institution{\todo{institution}}\country{\todo{country}}}
\email{aalhadsawane@gmail.com}

\begin{abstract}
Short serverless functions spend most of their time waiting for an isolated environment to start or for packets to cross a
long distance, while computers close to users sit idle. We ask whether idle consumer computers can answer requests that
must finish within seconds. Two things make this hard. Owners switch machines off without warning, which destroys every
prepared environment on them. And owners cannot be trusted with the code and data they run.
Remote attestation, in which a machine proves to a verifier which software it booted, changes the second problem: an owner
who controls the machine's software, power and network can still stop or delay it, but can no longer read or forge
anything. What is left is a scheduling problem. Proving trust, handing a machine a customer's decryption key, and starting
environments are slow; all of it is lost when the owner switches off; and every extra machine that holds a key is one more
place it could leak from.
We present \voss{}, a scheduler built for this problem. A planner, run every 30 seconds, decides which machines hold which
keys and ready environments, with spare capacity for machines that disappear. A per-request step then picks a machine for
each call and duplicates calls at risk. A machine is judged failed when work it accepted does not come back, not when it
stops sending heartbeats, and a failed scheduler is replaced without any agreement protocol among volunteers. We describe
two architectures, one global scheduler on provider hardware and geographic clusters with volunteer-hosted schedulers
reached through a publish/subscribe broker.
In a deterministic simulator calibrated on a TPM-equipped laptop, \voss{} keeps 99th-percentile latency under 3\,s in
\ViabAPThreeVoss{} of \ViabACells{} churn-and-adversary settings and \ViabBPThreeVoss{} of \ViabBCells{} settings that vary the trust technology and load,
where the strongest simple baseline does so in none. We also report the parts that did not pay off.
\end{abstract}
