## Session boot (Part C, host mode, 10 boots)

The v2 image mode was attempted first. This host is Ubuntu 22.04 with mkosi 12 and no `systemd-repart` or `ukify`;
the v2 `mkosi.conf` (`UnifiedKernelImages`, `[Validation] Verity`, `Encrypt=tpm2`) is not supported, so the image
was not built. The documented host-mode probe (D-60) was used instead; it boots the machine's own kernel and a
minimal one-shot target, runs the same TPM attestation round, and logs wall-clock stamps (±1 s). It gives the two
values the simulator consumes, `reboot_to_kernel` and `appliance_userspace`, but not the image-mode per-step
`boot_*` entries.

- CPU governor: `powersave` → `performance` before quick/full, and again before the ML/topup re-run;
  restored to `powersave` afterwards.
- Turbo: unchanged (`intel_pstate/no_turbo=0`).

  cluster node).
- Docker containers `helixml-*` stopped for Part B/Part C and for the ML/topup re-run, and started again.
- Diagnostic package `mkosi` 12 installed to test the image build, then purged.
- Host-mode boot loop: units installed, 10 boots run, units uninstalled, default target restored to
  `multi-user.target`; RTC left in UTC.
- Topup updated only the guest runner inside the two existing guest images; the Python, packages, functions and
  model weights are unchanged. New image hashes are in `assets.sha256`.
- The discarded 2026-11-16 ML raw run and its logs were archived outside the repository before the re-run.
- No BIOS change, no kernel-parameter change, no partition or raw-device write.
- Scratch directories were created on the NVMe and HDD; benchmark files are deleted by the suites.
