# Calibration notes: bare-metal host `node01-i7-12700-64g-nvme`

Machine: ASUS PRIME Z790-P WIFI (Rev 1.xx), Intel Core i7-12700 (12 cores / 20 threads, Alder Lake), 64 GB
DDR5-4800, 2 × 1 TB Samsung 980 PRO NVMe (no SATA SSD, no HDD), Intel PTT firmware TPM 2.0, Ubuntu 22.04.5 LTS,
kernel `5.15.0-198-generic`. Full specification and hashed serials: [`calibration/specs/node01-i7-12700-64g-nvme/SPEC.md`](../../calibration/specs/node01-i7-12700-64g-nvme/SPEC.md).
Node number `node01` was assigned by the human; the label follows NODE_PLAN §3.

## Human answers (CALIBRATION_HANDOFF §0.4)

- **Which machine / earlier session:** this is the ASUS PRIME Z790-P WIFI i7-12700 node. Earlier i7-12700 sessions
  exist in the repository (an MSI PRO Z790-A machine and an ASUS NVMe-only machine, under the old `i7-12700-64g`
  labels); they were not reused. Every number below was measured again in this session, from a fresh raw tree.
- **Parts run today:** A-D calibration. Part E is later, after `v2-freeze`.

  disabled. Owner class M is therefore not claimed for this node.
- **Scratch:** `/home/USER/voss-calib-work/scratch/nvme0` on the LVM/ext4 NVMe root (no other disk class exists).

## ML stage (harness `1de5d147`)

`node_run.sh ml` built the separate `voss-guest-ml.ext4` (PyTorch 2.4.1 CPU + ResNet-50 weights) and measured
`image-recognition` alone. Duration from `timeline.csv`: **build 60 s, sebs 110 s** (08:30:34–08:33:42 UTC on
2026-11-16; the stage total including the hand-off is about 3 min). The ML image SHA-256 is recorded in
`assets.sha256`.

- Handler medians (concurrency 1): 0.0749 s at size 50 and 0.0748 s at 100 (both 224×224, one image), 0.2836 s at 400
  (448×448, one image). These are consistent with a CPU ResNet-50 forward pass and are not implausible next to the
  other functions (thumbnailer/uploader are milliseconds; the graph functions and dna-visualisation are the slow ones).
- Init: 1.46 s (torch import + model load). RSS: 749 MB in the 2,048 MB guest (bundle median over co-run levels 737 MB).
  Snapshot: 2,048 MB, exactly the guest memory file.
- `image-recognition` co-run 20 was skipped by the RAM budget (40,960 MB); levels 1,2,4,8,12 were measured.
- The earlier Part B bundle had image-recognition skipped (no torch); this ML stage is the only repeated measurement.

Bundle: `configs/calibration/measured/node01-i7-12700-64g-nvme_nvme/`. The contract check reports **7 errors, 1

its bundle mixes every raw fingerprint under `calibration/raw`; the clean bundle above was produced with the explicit
`--host c0-584bb563fe` (the node's fingerprint). The driver's missing `--host` is a harness bug for the builder.

Raw evidence: `calibration/raw/c0-584bb563fe/` (committed, scrubbed; 9.3 MB before the ML run, plus the ML sebs
directory). External backups:

- `image-recognition` in Part B: skipped because the base guest image had no torch; measured in the ML stage (above).
- Co-run levels over the 60% RAM budget: `dynamic-html` 12/20, `dna-visualisation` 12/20, `image-recognition` 20,
  `graph-pagerank`/`graph-mst`/`graph-bfs` 20. Recorded as `skipped` in the raw logs; not estimated.
- Part C: 5/10 boots; boots 3–4 `boot_incomplete` after the kernel panic; boot 5 is a recovery outlier. The six
  image-only boot steps and `image_mem` are missing; the real UKI image needs systemd-repart/mkosi not available on
  Ubuntu 22.04. No BIOS/TME run was made.
- Handler span warning: 2.4e-05–3.6 s, not <1 ms to >10 s. No published SeBS comparison is configured.
- Contract gaps in the harness, not filled with estimates: `fn_input_gen` is not logged (the input is built before the
  timer, but its duration is not recorded); `dispatch_warm` and `fn_corun_mixed` are not implemented; `unseal` has n=20
  (contract 50) and is not mapped into the bundle under the contract name `tpm2_unseal`; `hash_per_MB` has n=5
  (contract 20).
- `unseal`/`hash_per_MB` small n: the suites record one distribution per configuration; the values above are measured,
  not copied.

## Conclusion

The node is calibrated for start-up, crypto, keys and all ten functions on NVMe. The Part B bundle is complete except
for the image-only Part C steps (host mode, 5/10 boots after the panic) and the `image_mem` constant; `check_bundle`
reports those seven errors and the handler-span warning. The ML gap is closed. Nothing from another node or an earlier
run was reused; the Part C logs show the actual boots, including the incomplete ones.
